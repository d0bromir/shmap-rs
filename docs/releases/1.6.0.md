# 1.6.0: Native Adaptive Long-Read Mapping

A minor release adding opt-in capabilities. The original mapper remains the
default; the adaptive path deliberately reports different, estimated placements.
No external mapper is integrated, invoked, or used as fallback.

## New Capabilities

- `--adaptive`: progressive positional sampling with orientation-aware voting,
  local verification, and native original-mapper fallback for unresolved reads.
- `--compact-index` and `--index-cache`: optional compact postings and persistent
  indexes with checksums, parameter validation, reference identity checks, and
  optional full reference hashing via `--verify-index-reference`.
- `--adaptive-dense`: experimental regional dense repeat rescue using
  candidate-local scans and separated distinguishing evidence.
- `--read-batch-size` and `--reader-threads`: batched dispatch/collection and
  ordered parallel parsing of uncompressed FASTA; other formats retain the
  original reader. Parser workers are additional to mapping workers.
- Direct jumps over empty buckets, reused worker diagnostics, and a native-only
  host benchmark driver with reproducible reports and retained raw evidence.

## Measured Results

Both host jobs completed: 180 measurements on a2 (three repeats) and 60 on
galaxy (one repeat), B01-B05, Containment, 1/16/64 mapping workers. All passed
the driver's PAF validation and determinism checks; normalized PAF hashes match
across architectures, worker counts, and repeats within each mode.

B04, real HiFi at 10x depth, 64 mapping workers:

| Host | Default Wall | Adaptive + Parsing Wall | Whole-Run Speedup | Mapping Speedup |
| --- | ---: | ---: | ---: | ---: |
| a2 | 31.78 s | 19.15 s | 1.66x | 2.27x |
| galaxy | 21.68 s | 11.47 s | 1.89x | 2.57x |

The parsing configuration uses two additional reader workers. Index construction
is included; inputs are page-cache warmed and index caches are not reused.
This is a comparison between bundled modes of the same binary, not an isolated
optimization ablation or comparison against an older release.

On B02, all modes mapped 125,000 simulated reads. Default and adaptive modes
placed 123,977 correctly; dense rescue placed 123,981 (true segment/strand and
IoU above 0.1). Both endpoints within 1 kb improved from 97,676 to 117,470 with
adaptive mapping and 117,763 with dense rescue. These are simulated-read results,
not real-read accuracy measurements.

## Limitations and Regressions

- **No 10x gain.** Dense mode regressed end-to-end in every measured case;
  repeat indexing took 178-395 seconds and peak RSS reached about 26.6 GiB.
- ONT B05 regressed end-to-end in all experimental configurations. Smaller
  B01-B03 workloads regressed at 16/64 workers despite faster mapping, because
  index setup offsets the savings. Keep experimental flags opt-in.
- Adaptive records have estimated coordinates and match counts, with
  `am:Z:adaptive-v1` or `am:Z:adaptive-dense-v1` and sampled-evidence tags rather
  than a full-sketch `J:f:` score. **MAPQ 255 means unavailable, not confidence.**
- General repeat/cross-individual accuracy, confidence calibration, native
  noisy/split-read handling, and cold-cache behavior remain unvalidated.
- The reduced native experiment is not the full maintained suite gate.
